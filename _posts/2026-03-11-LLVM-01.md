# Understanding LLVM's Modular Design

## What is LLVM's Modular Architecture?

LLVM is a compiler infrastructure composed of multiple reusable libraries. In this tutorial, we'll explore LLVM's architecture and design through its optimizer.

Since LLVM's optimizer is already packaged as a library, we can easily run various optimization passes. Users can selectively apply optimization passes based on their specific needs.

## LLVM Code Representations

To work with LLVM effectively, it helps to understand how LLVM represents code:

| Representation | Location | Description |
|----------------|----------|-------------|
| **IR** (Intermediate Representation) | Memory | In-memory representation used during compilation |
| **Bitcode** (.bc) | Disk | Binary format for storage and distribution |
| **Assembly** (.ll) | Disk | Human-readable text format |

## Static Single Assignment (SSA)

LLVM uses SSA-based representation, which provides:

- **Type safety** - Strong typing prevents many classes of bugs
- **Low-level operations** - Direct mapping to machine operations
- **Flexibility** - Easy to analyze and transform
- **Clean high-level language support** - Straightforward compilation from source languages

## Hands-On Example

Let's apply two different optimizations to the same code and observe how each one transforms it.

### Step 1: Create the Test File

Create a file named `testfile.ll` with the following LLVM IR:

```llvm
define i32 @test1(i32 %A) {
    %B = add i32 %A, 0
    ret i32 %B
}

define internal i32 @test(i32 %X, i32 %dead) {
    ret i32 %X
}

define i32 @caller() {
    %A = call i32 @test(i32 123, i32 456)
    ret i32 %A
}
```

### Step 2: Apply Instruction Combining

Run the **instcombine** pass to combine redundant instructions:

```bash
opt -passes=instcombine -S testfile.ll -o output1.ll
```

> **Note:** The `-S` flag outputs LLVM IR in text format (.ll). Omit `-S` to output bitcode (.bc) instead.

### Step 3: Examine the Result

```llvm
; ModuleID = 'testfile.ll'
source_filename = "testfile.ll"

define i32 @test1(i32 %A) {
  ret i32 %A
}

define internal i32 @test(i32 %X, i32 %dead) {
  ret i32 %X
}

define i32 @caller() {
  %A = call i32 @test(i32 123, i32 456)
  ret i32 %A
}
```

The redundant instruction has been optimized:

```llvm
; Before                    ; After
%B = add i32 %A, 0    →    ret i32 %A
ret i32 %B
```

Adding zero to `%A` is a no-op, so the optimizer eliminates the unnecessary addition.

### Step 4: Apply Dead Argument Elimination

Now let's run the **deadargelim** pass:

```bash
opt -passes=deadargelim -S testfile.ll -o output2.ll
```

### Step 5: Examine the Result

```llvm
; ModuleID = 'testfile.ll'
source_filename = "testfile.ll"

define i32 @test1(i32 %A) {
  %B = add i32 %A, 0
  ret i32 %B
}

define internal i32 @test(i32 %X) {
  ret i32 %X
}

define i32 @caller() {
  %A = call i32 @test(i32 123)
  ret i32 %A
}
```

Notice that `@test1()` remains unchanged, but in `@test()`, the unused argument `i32 %dead` has been removed along with its corresponding call site argument.

## Key Takeaways

From this example, we can observe several important aspects of LLVM's design:

1. **Loosely Coupled Passes** - LLVM's optimizer provides various passes that are not tightly coupled to each other.

2. **Pass Manager** - LLVM's pass manager maintains dependency information between passes, connecting them only when needed during execution.

3. **Selective Optimization** - LLVM includes many built-in passes that users can selectively enable based on their optimization goals.
